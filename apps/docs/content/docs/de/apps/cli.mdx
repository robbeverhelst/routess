`routess` ist die offizielle CLI. Sie kapselt dieselbe REST-API, die auch die Web-App nutzt, und ist der Einstiegspunkt für Agenten und CI, um Routen ohne Browser zu lesen und zu bearbeiten.

## Installation

```sh
npm install -g routess
```

Das Binary heißt `routess`. Es benötigt Node 20+ (das veröffentlichte Bundle ist ESM).

## Authentifizieren

Die CLI spricht mit der API über ein Personal Access Token (PAT). Erstelle eines in der Web-App unter **Settings -> API Tokens** und melde dich danach entweder einmal an oder übergib das Token per Umgebungsvariable.

```sh
# Interactive: persists the token to ~/.config/routess/auth.json (mode 0600).
routess auth login --token routess_pat_...

# Stateless: skip local storage. Useful for CI and ephemeral containers.
export ROUTESS_TOKEN=routess_pat_...
```

`ROUTESS_TOKEN` hat Vorrang vor der Datei auf der Festplatte. Die Token-Speicherung folgt der XDG-Konvention: `$XDG_CONFIG_HOME/routess/auth.json`, falls gesetzt, andernfalls `~/.config/routess/auth.json`.

Richte die CLI mit `ROUTESS_API_URL` oder dem Flag `--api-url` beim Login auf eine andere API. Standard ist `https://api.routess.com`.

```sh
routess auth whoami       # confirm you're signed in
routess auth logout       # delete the on-disk token
```

## Befehle

Hänge `--json` an einen beliebigen Befehl an, um maschinenlesbare Ausgabe zu erhalten. Fehler im `--json`-Modus geben auf stderr ein `DomainErrorPayload` aus, das das Fehlerformat der API spiegelt, sodass Agenten direkt anhand von `code` verzweigen können.

### Routen

```sh
routess routes list --limit 20 --offset 0   # your routes, newest first
routess routes public                       # indexable public routes (no auth needed)
routess routes get <id>
routess routes gpx <ref> -o ride.gpx        # download GPX; <ref> is an id or a 32-hex share token
routess routes create --from route.json     # CreateRoute JSON payload; "-" reads stdin
routess routes import ride.gpx --name "Sunday loop" --activity cycling
routess routes update <id> --name "New name" --description "..." --tags gravel,hilly
routess routes update <id> --visibility public --confirm
routess routes favourite <id>               # and unfavourite
routess routes delete <id> --confirm
```

`list` und `public` geben `showing X of Y` aus dem Header `X-Total-Count` aus und akzeptieren `--limit` / `--offset`. `import` nimmt dieselben `--activity`-IDs wie die API (`cycling`, `running`, `hiking`, ...) und erstellt standardmäßig eine private Route; ein leerer Wert für `--description` oder `--tags` leert das Feld.

### Sammlungen

```sh
routess collections list
routess collections get <ref>
routess collections create --name "Alps 2026" --visibility unlisted
routess collections update <id> --name "New name"
routess collections set-routes <id> --routes id1,id2,id3
routess collections delete <id> --confirm
```

`set-routes` ersetzt die gesamte geordnete Mitgliederliste (ein leerer Wert leert die Sammlung). Das Löschen einer Sammlung behält die Routen darin.

### Rundstrecken generieren

```sh
routess generate --start 50.8467,4.3525 --activity cycling --distance 40
routess generate ... --heading n --surface gravel --gpx-dir ./candidates
routess generate ... --save 2 --name "Generated loop"
```

Die Generierung benötigt keine Authentifizierung und gibt bis zu drei bewertete Kandidaten mit Peilung, Distanz, Dauer, Überlappung und Untergrundmischung aus. `--gpx-dir` schreibt jeden Kandidaten als `candidate-<n>.gpx`; `--save [n]` speichert den Kandidaten `n` (Standard 1) als private Route in der Bibliothek, was ein write-Token erfordert. `--exclude-bearings` generiert frische Formen neu und spiegelt damit "Andere Rundstrecken zeigen" der Web-App.

### Tokens und Kontoexport

```sh
routess tokens list                # metadata only, plaintext is never shown
routess tokens revoke <id>
routess export -o my-data.zip     # routess-export.json plus one GPX per route
```

Das Widerrufen des Tokens, mit dem die CLI gerade authentifiziert ist, sperrt dich aus, daher erfordert es `--confirm`.

### Bestätigungs-Gates

Destruktive oder nach außen gerichtete Operationen erfordern ein ausdrückliches `--confirm`: das Löschen von Routen oder Sammlungen, das Setzen einer beliebigen Sichtbarkeit auf `public` und das Widerrufen des aktiven Tokens. Ohne es beendet sich die CLI mit Code 9 (Vorbedingung erforderlich).

## Exit-Codes

Die CLI nutzt eine stabile Exit-Code-Taxonomie, die an den Domain-Fehlercodes der API ausgerichtet ist. Agenten verzweigen darauf gleich, unabhängig davon, ob der Fehler lokal auftrat oder vom Server zurückkam.

| Code | Bedeutung                  |
| ---- | ------------------------ |
| 0    | OK                       |
| 1    | Generischer / unbekannter Fehler  |
| 2    | Nutzungsfehler              |
| 3    | Validierung fehlgeschlagen        |
| 4    | Nicht gefunden                |
| 5    | Nicht autorisiert (kein Token oder Token abgelehnt) |
| 6    | Verboten (Token fehlt der erforderliche Scope) |
| 7    | Konflikt                 |
| 8    | Rate-Limit erreicht             |
| 9    | Vorbedingung erforderlich    |
| 10   | Netzwerkfehler            |
| 11   | Interner Serverfehler    |

## Scopes

PATs tragen einen von zwei Scopes: `read` (GET-Endpunkte, einschließlich des Kontoexports) oder `write` (mutierende Endpunkte: POST, PATCH, DELETE). Die CLI meldet ein `FORBIDDEN` (Exit-Code 6), wenn du versuchst, eine Route mit einem read-only-PAT zu verändern; erstelle in der Web-App ein write-scoped Token und authentifiziere dich erneut.

Öffentliche Oberflächen funktionieren ohne jedes Token: `routes public`, `routes gpx` / `collections get` auf öffentlichen oder Share-Token-Referenzen sowie `generate` (ohne `--save`).

Die vollständige Endpunktliste und die Scope-Anforderungen pro Endpunkt findest du in der [API-Referenz](../../api).
