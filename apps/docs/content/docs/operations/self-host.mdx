This walkthrough gets a routess instance running on your own machine or server in about five minutes. For Kubernetes, see [Kubernetes](./kubernetes).

## What you need

- **Docker** and **Docker Compose v2** (modern Docker Desktop or Docker Engine ships with both).
- A **Google OAuth client** for Google sign-in (the compose file requires it). Users can also sign in with email + password once the stack is up.
- A **Mapbox access token**; the free tier is fine.
- Long random strings for `JWT_SECRET`, `ANALYTICS_SALT`, `PAT_PEPPER`, and `DB_PASSWORD`. Generate with `openssl rand -base64 32`.

Optional, gracefully disabled when unset:

- **Resend** for transactional email (without it, verification URLs are logged to stdout).
- **Valhalla** for surface-type analysis on planned routes.
- **Sentry / GlitchTip** for browser error reporting.
- **Umami** for product analytics.
- **Admin role** for accessing the in-app admin panel.

## Set up Google OAuth

1. Open the [Google Cloud Console credentials page](https://console.cloud.google.com/apis/credentials).
2. Create an **OAuth 2.0 Client ID** of type **Web application**.
3. Under **Authorized JavaScript origins**, add the URL your users will open (e.g. `http://localhost:8080` or `https://routess.example.com`).
4. Under **Authorized redirect URIs**, add `<your-web-url>/auth/callback`.
5. Copy the **Client ID** and **Client secret**.

## Get a Mapbox token

1. Sign up at [account.mapbox.com](https://account.mapbox.com).
2. Create a public access token (`pk.…`) under **Access tokens**.
3. Restrict it to your domain when you go to production.

## Run it

```sh
git clone https://github.com/robbeverhelst/routess.git
cd routess
cp docker/.env.selfhost.example .env
# edit .env and fill in the required values
docker compose -f docker/compose.selfhost.yaml --project-directory . up -d
```

Then open [http://localhost:8080](http://localhost:8080).

The stack starts four containers:

| Service  | Image                                      | Default port |
| -------- | ------------------------------------------ | ------------ |
| Postgres | `postgres:18`                              | (internal)   |
| API      | `ghcr.io/robbeverhelst/routess-api`        | `3000`       |
| Web      | `ghcr.io/robbeverhelst/routess-web`        | `8080`       |
| Docs     | `ghcr.io/robbeverhelst/routess-docs`       | `3002`       |

Change the host ports via `WEB_PORT`, `API_PORT`, `DOCS_PORT` in `.env`.

## Pin a version

Default tag is `latest`. For production, pin to a specific release:

```sh
ROUTESS_TAG=1.122.7 docker compose -f docker/compose.selfhost.yaml --project-directory . up -d
```

Or set `ROUTESS_TAG` in `.env`. See the [releases page](https://github.com/robbeverhelst/routess/releases) for available tags.

## Environment variables

The `.env` file in `docker/.env.selfhost.example` is the source of truth. The variables you'll touch most often:

| Variable                       | Required | Default                          | Purpose                                                                                  |
| ------------------------------ | -------- | -------------------------------- | ---------------------------------------------------------------------------------------- |
| `JWT_SECRET`                   | yes      | -                                | Signs session and API tokens. Rotating logs everyone out.                                |
| `ANALYTICS_SALT`               | yes      | -                                | Hashes user IDs in analytics events. Rotating resets the analytics pseudonyms.            |
| `PAT_PEPPER`                   | yes      | -                                | Hashes personal access tokens at rest. Rotating invalidates every existing PAT.          |
| `DB_PASSWORD`                  | yes      | -                                | Postgres password.                                                                       |
| `GOOGLE_CLIENT_ID/SECRET`      | yes      | -                                | Google OAuth credentials.                                                                |
| `VITE_MAPBOX_ACCESS_TOKEN`     | yes      | -                                | Mapbox access token used by the web app.                                                 |
| `PUBLIC_WEB_URL`               | no       | `http://localhost:8080`          | Where users open the app. Used as OAuth redirect base.                                   |
| `PUBLIC_API_URL`               | no       | `http://localhost:3000`          | Where the web app reaches the API.                                                       |
| `ADMIN_EMAILS`                 | no       | empty                            | Comma-separated emails granted the admin role on login. Empty disables the admin panel. |
| `RESEND_API_KEY`               | no       | empty                            | Resend API key. Empty falls back to logging verification URLs to stdout.                 |
| `EMAIL_FROM`                   | no       | `routess <noreply@routess.app>`  | Sender address used by Resend.                                                           |
| `VALHALLA_URL`                 | no       | empty                            | Base URL of a self-hosted Valhalla instance for surface analysis. Empty disables it.     |
| `VITE_UMAMI_URL` / `_WEBSITE_ID` | no     | empty                            | Umami endpoint and site ID for the web app. Empty disables product analytics.            |
| `UMAMI_URL` / `_WEBSITE_ID`    | no       | empty                            | Same Umami endpoint and site ID for the docs site (Next reads them server-side).         |
| `VITE_SENTRY_DSN`              | no       | empty                            | Sentry / GlitchTip DSN for browser error reporting.                                      |
| `VITE_SENTRY_ENVIRONMENT`      | no       | `production`                     | Environment tag attached to browser error reports.                                       |
| `PUBLIC_DOCS_URL`              | no       | `http://localhost:3002`          | Canonical origin of the docs site, used in its sitemap, robots.txt, and llms.txt links.  |

## Advanced variables

The API understands more knobs than the compose file passes through. To use one, add it under the `api` service `environment` in `docker/compose.selfhost.yaml` (or your own override file):

| Variable                       | Default            | Purpose                                                                                      |
| ------------------------------ | ------------------ | -------------------------------------------------------------------------------------------- |
| `LOG_LEVEL`                    | `info`             | Pino log level for the API (`debug`, `info`, `warn`, `error`).                               |
| `SESSION_TTL_DAYS`             | `7`                | How long a browser session stays valid.                                                      |
| `SESSION_COOKIE_NAME`          | `routess_session`  | Name of the HTTP-only session cookie.                                                        |
| `JWT_EXPIRES_IN`               | `7d`               | JWT token lifetime.                                                                          |
| `FRONTEND_URLS`                | empty              | Comma- or newline-separated list of allowed web origins; overrides `FRONTEND_URL` when set.  |
| `SWAGGER_ENABLED`              | `false` in prod    | Serve interactive API docs at `SWAGGER_PATH`.                                                |
| `SWAGGER_PATH`                 | `/api`             | Path for the Swagger UI when enabled.                                                        |
| `TELEMETRY_ENABLED`            | `true`             | Master switch for OpenTelemetry (metrics + traces).                                          |
| `METRICS_ENABLED`              | `true`             | Prometheus metrics at `/metrics` on the API port. Returns 503 when disabled.                 |
| `OTEL_EXPORTER_OTLP_ENDPOINT`  | empty              | OTLP collector base URL for traces (`/v1/traces` is appended). Empty disables trace export.  |
| `OTEL_EXPORTER_OTLP_HEADERS`   | empty              | Extra OTLP headers as a JSON object, e.g. `{"authorization":"Bearer …"}`.                    |
| `GRAFANA_URLS`                 | empty              | JSON object of dashboard links shown in the admin panel: `{"apiOverview":"…","apiLatency":"…","runtime":"…"}`. |

For the web container:

| Variable                          | Default | Purpose                                                              |
| --------------------------------- | ------- | --------------------------------------------------------------------- |
| `VITE_SENTRY_TRACES_SAMPLE_RATE`  | `0.1`   | Fraction of browser sessions traced when Sentry is enabled.           |
| `VITE_SENTRY_LOGS_ENABLED`        | `false` | Forward browser logs to Sentry.                                       |
| `VITE_SENTRY_DEBUG`               | `false` | Verbose Sentry SDK logging.                                           |

Browser console logging defaults to `warn`. To debug a single browser, set `localStorage["routess:log-level"]` to `debug`, `info`, `warn`, `error`, or `none` and reload.

## Put it behind a reverse proxy

The default compose exposes ports directly. For TLS and a real domain, front the `web` and `api` services with a reverse proxy (Caddy, Traefik, ingress-nginx, Cloudflare Tunnel) and override the public URLs in `.env`:

```sh
PUBLIC_WEB_URL=https://routess.example.com
PUBLIC_API_URL=https://api.routess.example.com
```

`PUBLIC_WEB_URL` is also used as the OAuth redirect base, so it must match what you configured in Google Cloud.

## Upgrade

Take a database backup first (see below); migrations are forward-only, so a snapshot is your rollback path. Then:

```sh
docker compose -f docker/compose.selfhost.yaml --project-directory . pull
docker compose -f docker/compose.selfhost.yaml --project-directory . up -d
```

The API runs migrations automatically on startup. There is no manual migration step. To roll back, restore the pre-upgrade dump and pin `ROUTESS_TAG` to the previous release.

## Back up

The Postgres data lives in the `postgres_data` named volume. Standard `pg_dump` works:

```sh
docker compose -f docker/compose.selfhost.yaml --project-directory . exec postgres \
  pg_dump -U routess routess > routess-$(date +%F).sql
```

Restore into a fresh volume with `psql`:

```sh
docker compose -f docker/compose.selfhost.yaml --project-directory . exec -T postgres \
  psql -U routess routess < routess-2026-06-04.sql
```

## Troubleshooting

- **Is the API healthy?** `curl http://localhost:3000/health/ready` returns 200 when the API can reach the database; `/health/live` checks only that the process is up.
- **"address already in use"** on `:8080` or `:3000`: change `WEB_PORT` / `API_PORT` in `.env`.
- **Google sign-in returns `redirect_uri_mismatch`**: the OAuth client's authorised redirect URI must exactly match `<PUBLIC_WEB_URL>/auth/callback`.
- **Map tiles don't load**: verify `VITE_MAPBOX_ACCESS_TOKEN` is set; check browser devtools for 401s from `api.mapbox.com`.
- **Verification emails not arriving**: set `RESEND_API_KEY` and `EMAIL_FROM`. Without them the API logs the verification URL to stdout; run `docker compose logs api | grep '\[email:console\]'`.
