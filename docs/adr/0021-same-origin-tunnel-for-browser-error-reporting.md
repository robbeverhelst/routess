# Same-origin nginx tunnel for browser error envelopes

Extends ADR-0019. EasyPrivacy (the default filter list shipped with uBlock Origin, AdBlock Plus, Ghostery, Brave Shields) blocks any URL containing `?sentry_key=` or `?sentry_version=` regardless of host, so the Sentry SDK's direct POST to `glitchtip.robbe.work/api/N/envelope/?sentry_key=…` is dropped by `~30-40%` of the dev-tech audience before it leaves the page. The fix is a forward proxy that the SDK posts to instead, configured via the SDK's `tunnel` option, which omits the blocked query parameters and embeds the DSN in the envelope body. The tunnel lives in the `apps/web` nginx pod at the path `/__t` on the same origin as the SPA, *not* on the `routess-api` host: same-origin keeps the request off any current and future cross-host filter rules, the tunnel stays up when the API is down (which is exactly when we most want errors to flow), and a `location` block in the nginx config is cheaper than a NestJS route. The upstream URL is derived at container start from `VITE_SENTRY_DSN` (host + project id), so ADR-0019's invariant "switching to hosted Sentry is a DSN swap, not a code change" still holds; `entrypoint.sh` parses the DSN and writes `/etc/nginx/conf.d/tunnel.conf` only when DSN is set, leaving the location absent (404) when GlitchTip is not configured to preserve the silent-passthrough guarantee from ADR-0019. The SDK is wired with `tunnel: import.meta.env.PROD ? '/__t' : undefined` so `bun dev` against a real GlitchTip still works without a Vite dev-server proxy. `X-Forwarded-For` is stripped at the nginx layer so GlitchTip records the pod IP rather than the client IP, preserving the `sendDefaultPii: false` posture from ADR-0019. No allowlist is enforced on the tunnel: the upstream is hardcoded (templated from DSN) to your single GlitchTip project, so the worst an abuser can do is spam *that* project, which they could already do by hitting `glitchtip.robbe.work/api/1/envelope/` directly. The path `/__t` was chosen over `/api/t`, `/relay`, or `/sentry-tunnel` to (a) avoid the fictional `/api/*` namespace on the web origin (the real API lives on a separate ingress), (b) signal "internal infrastructure" via the `__` prefix, and (c) stay off generic descriptive-name patterns that descriptive paths like `/relay` or `/telemetry` would invite.

## Considered options

- **NestJS route on `routess-api`** (the original issue's proposal) rejected: the API rides a separate ingress (`api.routess.com`), so the tunnel is cross-origin from the SPA. CORS preflight on every event adds overhead and a second adblocker-rule surface. More importantly, the tunnel goes down whenever the API pod is unhealthy, which is precisely the window where browser-side errors about that outage would be most valuable.

- **Hardcoded upstream in `nginx.conf`** rejected: forks need to edit the image to point at their own GlitchTip, and the "DSN swap is the only knob" invariant from ADR-0019 silently breaks. Templating from `VITE_SENTRY_DSN` keeps the DSN as the single source of truth for both the SDK and the tunnel.

- **DSN public-key allowlist enforced inside the tunnel** rejected: defends a threat model that does not exist here. The upstream is hardcoded to a single GlitchTip project; an attacker who finds the tunnel can spam *that* project with bogus events, which is identical to the abuse surface of GlitchTip's own envelope endpoint. Adding the allowlist would require parsing the envelope's first NDJSON line in `njs` or Lua, abandoning the "pure nginx" simplicity for no security gain.

- **Path `/api/t` (per the original issue)** rejected: the web origin has no `/api/*` namespace, so the name implies a fictional API surface. `/__t` is honest about being internal plumbing.

- **Forwarding `X-Forwarded-For` to GlitchTip** rejected: contradicts ADR-0019's explicit "no IP" stance. GlitchTip would record the real client IP on every event despite `sendDefaultPii: false` on the SDK side. If geographic error grouping turns out to matter, revisit deliberately (hashed IP, separate ADR) rather than backslide into raw-IP storage by default.

- **Tunnel always on, including dev** rejected: `bun dev` runs Vite's dev server with no nginx, so `tunnel: '/__t'` would make every event 404 silently. `import.meta.env.PROD` is the canonical Vite signal for "this is the built bundle" and exactly matches the population that runs behind the templated nginx.

- **Service-worker exclusion for `/__t`** unnecessary: `apps/web/public/sw.js:123` already skips non-GET requests, so envelope POSTs are not intercepted. No SW change required.
